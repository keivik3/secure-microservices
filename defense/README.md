# Материалы защиты

## Краткое обоснование проекта

Rail Repair — приложение для учёта заявок на ремонт железнодорожной
инфраструктуры. Оно позволяет регистрировать дефекты, назначать
ремонтную бригаду, отслеживать статус работ и передавать события сервису
уведомлений.

Проект решает задачу централизованного учёта дефектов: вместо разрозненных
сообщений и таблиц каждая заявка имеет единый набор данных и контролируемый
жизненный цикл. Это снижает риск потери информации и позволяет видеть текущее
состояние ремонта.

Микросервисная архитектура выбрана для разделения функций: API Gateway
принимает HTTP-запросы, Repair Service выполняет бизнес-логику, а Notification
Service обрабатывает события. PostgreSQL хранит заявки, Redis ускоряет
чтение, RabbitMQ развязывает основной сервис и обработчик уведомлений.

Для проекта важны безопасность и надёжность, потому что потеря или недоступность
данных о критическом дефекте может задержать ремонт. Поэтому в стенде
используются сетевая сегментация, резервное копирование, репликация PostgreSQL
и отказоустойчивая очередь RabbitMQ.
